FAQ

Answers to common questions

What is PDM?

PDM stands for Product Data Management. It's a system for organizing, versioning, and managing design files—especially important for CAD work where designs evolve and you need to track every change.

Traditional PDM (expensive)

Enterprise PDM systems like Autodesk Vault, Dassault 3DEXPERIENCE, or Windchill cost thousands of dollars per seat and require server infrastructure. They're built for teams and provide features like:

  • File locking (prevent conflicts when multiple people edit the same file)
  • Workflow approval processes
  • Permissions and role-based access
  • Integration with ERP systems

These are powerful but overkill for a solo designer.

What s3pdm does (free)

s3pdm is a lightweight personal PDM for solo SOLIDWORKS users. It gives you the core PDM features that actually matter for one person:

  • Version control—every file has complete history
  • Check-in with comments—document why you made changes
  • File management—organize by folders, see sizes and modification status
  • Restore—go back to any previous version instantly
  • Cloud storage—files live in S3, not on your local PC

No approvals, no team coordination, no enterprise overhead. Just straightforward version control for your designs.

How does this compare to Git?

Git and s3pdm overlap, but they're built around different ideas. For SOLIDWORKS files, the differences matter more than they first appear.

Where Git is Better

Project-wide snapshots

Every Git commit captures the whole project exactly as it was, so git checkout <commit> puts every part, assembly, and drawing back to a consistent state. s3pdm records which versions went together in each check-in, but you'd restore them file by file.

Branches and tags

You can explore a design variant on a branch or tag exactly what you sent a client. s3pdm has neither.

Maturity

Git is used by millions of people and extremely well tested. s3pdm is a few hundred lines that only you maintain, so a bug in it is your problem.

Offline commits

You commit locally and push later. s3pdm needs a connection to check in.

Where Git is Worse for CAD

Storage bloat

Git keeps every version of every file on every machine. Each 250 MB part you revise ten times puts 2.5 GB into your local .git folder, forever, on every computer that clones the repository. Git LFS fixes this by keeping large files on a server and downloading only the versions you need. But it adds setup, and its storage is either on GitHub (which charges for LFS space and bandwidth quickly) or a server you host yourself.

Binary files get none of Git's best features

It can't show a meaningful diff of a part file or merge two edits to an assembly, so you mostly get the storage and history parts of Git.

Workspace rewrites fail

Switching commits rewrites the whole working folder. That fails partway through if SOLIDWORKS has files open, and it can confuse SOLIDWORKS if it has files cached.

Mental model mismatch

Its mental model is the whole repository, not individual files. Staging, committing, pushing, and pulling is more ceremony than "check in this file with a comment," and TortoiseGit or GitHub Desktop help only somewhat.

What s3pdm Does Differently

History lives only in the cloud

Your PC holds just the current files, so there's no local history growing without limit.

Cheap and simple infrastructure

Any cheap S3 bucket is the whole "server." There's nothing to run or maintain.

PDM-like workflow

Its model matches PDM: individual files with version numbers and a comment on each check-in.

Direct file access

current/ is browsable, so you can get files out with any S3 tool, no Git knowledge required.

Recoverable storage format

The storage format is plain JSON and files, simple enough to recover by hand if the app ever breaks.

The In-Between Options

Two Git-based tools solve the large-file problem more cleanly than LFS, and both can use S3 or B2 directly as storage:

git-annex

Git tracks the history while file contents live in S3, and you only download the versions you ask for. It's very capable, but it has a steep learning curve and its Windows support is rough.

DVC

Aimed at data science, but it works for any large files. It's easier than git-annex, though still command-line oriented.

Either would give you Git's snapshots and branches without the storage bloat, at the cost of more complexity than s3pdm.

The Bottom Line

For solo SOLIDWORKS work where you want per-file versions, a simple GUI, and history kept off your PC, s3pdm is the better fit.

Git becomes the better choice if you find yourself wanting branches, or wanting to roll a whole project back to a known state. If it's mainly that second one, a "Restore this check-in" feature would be a small addition to s3pdm that would close most of that gap.
